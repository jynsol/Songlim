1. 개편 기준

이 문서는 기존의 “외부 데이터 수집·매칭 조사서”가 아니라, 현재 작동 프로토타입을 서버·DB로 옮기기 위한 데이터 정의서다. 화면에 실제 존재하는 상태, 기록, 집계, 숲 표현을 먼저 정의하고 외부 Provider는 그 데이터를 채우는 하위 계층으로 내린다.

3. 권장 도메인 모델

Provider/Share/Import/Search → Content → UserContent → SaveEvent / ExperienceLog / Completion / Review → Today / Scrap / Calendar / Forest
엔티티역할중요 필드
Content사용자와 무관한 작품 원본type, title, creator, genre, tree_category, length, cover, provider ids
UserContent사용자와 작품의 1:1 관계user_id, content_id, imported_progress, track_index, created_at
SaveEvent같은 작품을 몇 번/어디서 스크랩했는지source, source_url, saved_at, request_key
ExperienceLog책/음반의 날짜별 경험local_date, page_or_position, memo
Completion완료 사실completed_local_date, completed_at
Review별점·감상rating 1–5 nullable, review_text nullable
UserPreference프로필/온보딩 취향display_name, tastes, responses
ForestTheme연도별 숲 테마year, theme_id
TodaySelection오늘 경험 대상으로 명시 선택한 기록local_date, user_content_id, selection_source

프로토타입의 selected는 단일 로컬 상태지만, 서버 구현에서는 날짜 이력과 분석 가능성을 위해 TodaySelection 이벤트로 분리하는 편이 안전하다.

4. 상태와 전이 규칙

UI 상태판정식진입이탈
SAVED 아직 안 본 것completion 없음 AND experience log 없음 AND imported_progress=false최초 스크랩/직접 추가첫 기록 또는 완료
ACTIVE 경험 중completion 없음 AND (log ≥ 1 OR imported_progress=true)책/음반 첫 경험 기록, 기존 진행 데이터 import완료
DONE 완료completion 존재완료 처리완료 취소
중요: 상태는 중복 저장하지 않는 것을 권장한다. 프로토타입도 completed, logs, importedProgress로 상태를 계산한다. DB에 status를 둔다면 캐시/검색 최적화용 파생값으로 취급한다.

5. Content 스키마

Content - id: uuid PK - type: BOOK | ALBUM | MOVIE - title: text NOT NULL - creator_display: text - genre_raw: text nullable - tree_category: enum nullable # 수동 지정 시 우선 - length_value: int nullable # 책=쪽수, 음반/영화=분 - cover_url: text nullable - created_at / updated_at ContentExternalId - content_id FK - provider: KAKAO_BOOK | GOOGLE_BOOKS | MUSICBRAINZ | CAA | TMDB | KOBIS | ... - external_id: text - id_type: ISBN13 | RELEASE_GROUP_MBID | RELEASE_MBID | TMDB_ID | KOBIS_MOVIE_CD | ... - UNIQUE(provider, external_id, id_type)

프로토타입의 creator 단일 문자열은 UI 표시에는 충분하지만 운영 DB에서는 저자/아티스트/감독 배열을 별도 관계로 확장할 수 있다. MVP에서는 creator_display를 필수 표시값으로 두고 구조화 creator는 점진적으로 추가한다.

6. UserContent · 저장 이벤트

UserContent - id: uuid PK - user_id FK - content_id FK - imported_progress: boolean default false - track_index: int default 0 - created_at / updated_at - UNIQUE(user_id, content_id) SaveEvent - id: uuid PK - user_content_id FK - request_key: text nullable UNIQUE per user - source_type: DIRECT | SHARE | IMPORT | ONBOARDING | SEARCH | LEGACY - source_label: text nullable - source_url: text nullable - saved_at: timestamptz NOT NULL

스크랩 횟수는 COUNT(SaveEvent), 최근 저장은 MAX(saved_at)으로 계산한다. 동일 작품을 다시 저장해도 UserContent는 하나만 유지한다.

7. 경험 기록 · 완료 · 감상

ExperienceLog - id: uuid PK - user_content_id FK - local_date: date NOT NULL - page_or_position: text nullable - memo: text nullable - created_at / updated_at - UNIQUE(user_content_id, local_date) Completion - user_content_id PK/FK - completed_local_date: date nullable # legacy unknown 허용 시 nullable - completed_at: timestamptz NOT NULL Review - user_content_id PK/FK - rating: smallint nullable CHECK 1..5 - review_text: text nullable - updated_at

프로토타입은 책/음반에 같은 날짜의 경험 로그를 중복 생성하지 않고, 영화는 별도 일일 로그 없이 완료일을 경험일로 사용한다. 완료 취소 시 완료 정보와 별점이 제거되는 현재 동작이 있으므로, 실제 서비스에서는 감상까지 삭제할지 UX 정책을 확정해야 한다.

8. 오늘 데이터 규칙

오늘 탭은 추천 DB가 아니라 스크랩된 UserContent를 경험 상태로 전환시키는 작업 공간이다.

동작데이터 처리
오늘 경험할 콘텐츠 선택미완료 UserContent를 선택하고 TodaySelection 기록. 콘텐츠 자체는 복제하지 않음.
다른 콘텐츠 보기선택 후보만 교체. 저장 상태에는 영향 없음.
책/음반 경험 기록ExperienceLog upsert. 첫 로그부터 ACTIVE.
완료하고 나무 심기Completion 생성 → DONE → 해당 연도 숲 집계에 즉시 포함.
별점/감상Review 독립 저장. 둘 다 선택값.

10. 숲 · 월간 기록 집계

지표/화면계산
연도별 나무 수해당 연도 Completion 수
숲 면적완료 수 × 15㎡
유형별 완료BOOK / ALBUM / MOVIE group by
가장 많이 경험한 장르완료 콘텐츠를 tree_category로 group by 후 최대값
평균 별점해당 완료 콘텐츠 중 rating이 있는 항목만 AVG
월 기록한 날그 달 ExperienceLog 날짜 + 영화 Completion 날짜의 distinct count
월 완료 수completed_local_date가 선택 월인 Completion count
ForestTheme - user_id - year smallint - theme_id: BASIC | JUNGLE | SNOW - updated_at - UNIQUE(user_id, year)

프로토타입은 과거 호환값 autumn→jungle, winter→snow를 허용한다. 신규 DB에는 BASIC/JUNGLE/SNOW만 저장하고 migration에서 변환한다.

11. 외부 데이터 유입 · 매칭

외부 데이터는 핵심 도메인을 채우는 입력 계층이다. 기존 정의서의 원칙은 유지하되, 매칭 성공이 곧 사용자 저장을 뜻하지 않도록 분리한다.

Share / Image Import / Search / Onboarding → Candidate → Provider Verification → Entity Resolution → Content 확정 → 사용자 저장 확정 → UserContent + SaveEvent
유형주 데이터원운영 원칙
책Kakao Books + Google BooksISBN 우선 식별, 제목+저자 보조
음반MusicBrainz + Cover Art ArchiveRelease Group 중심, 캐시/큐 필요
영화TMDB + KOBISTMDB 상업 라이선스 확인 전 프로덕션 의존 금지
공유/이미지URL·공유텍스트·사용자 선택 이미지후보 추출 후 정식 Content DB로 검증. 낮은 신뢰도 자동 병합 금지

12. Supabase 권장 테이블

profiles contents content_external_ids user_contents save_events experience_logs completions reviews today_selections forest_themes user_tastes import_batches # import 기능 연결 시 import_candidates # import 기능 연결 시 source_assets # 원본 이미지 보관이 필요할 때만

현재 프로토타입의 로컬 JSON을 그대로 한 테이블에 넣기보다 위처럼 정규화하는 편이 RLS, 집계, 중복 방지, 향후 Provider 교체에 유리하다.

12.1 최소 제약조건

UNIQUE(user_contents.user_id, user_contents.content_id) UNIQUE(experience_logs.user_content_id, experience_logs.local_date) CHECK(contents.type IN ('BOOK','ALBUM','MOVIE')) CHECK(reviews.rating BETWEEN 1 AND 5 OR reviews.rating IS NULL) CHECK(forest_themes.theme_id IN ('BASIC','JUNGLE','SNOW')) RLS 기본 원칙 - contents: authenticated read, 서버/관리 경로 write - user_* / save_events / logs / completions / reviews: auth.uid() = owner user_id - provider raw payload: 클라이언트 직접 write 금지
