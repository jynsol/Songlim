송림

취향이 자라는 숲

사용자가 발견한 문화 콘텐츠를 경험 데이터로 축적하고, 시간이 지나 개인의 문화 자산과 취향 데이터로 성장시키는 문화 아카이빙 서비스

Service Problem Solution Experience Forest MVP BM 시장·경쟁 실행계획
01

Service Definition

송림은 사용자가 외부에서 발견한 콘텐츠를 공유하면 정보를 자동으로 인식·분류하고, 서로 다른 출처의 콘텐츠를 하나의 관심으로 연결해 실제 경험으로 이끄는 서비스다.

송림은 새로운 관심을 추천하는 서비스가 아니라, 내가 이미 관심을 보였지만 놓치고 있던 콘텐츠를 실제 경험으로 연결하는 서비스다. 사용자는 별도로 콘텐츠를 다시 검색하거나 일일이 분류할 필요 없이, 발견한 콘텐츠를 송림으로 보내기만 하면 된다. 송림은 공유된 콘텐츠의 정보를 자동으로 인식·정리하고, 사용자가 흩어놓은 관심을 하나의 경험 흐름으로 연결한다.

1. 공유 기반 가져오기
콘텐츠를 발견하면 모바일 OS 기본 공유 기능을 통해 송림으로 전달한다.

2. URL 입력
공유 기능을 사용할 수 없거나 정보가 부족한 경우, URL 복사·붙여넣기를 통해 추가할 수 있다.

3. 이미지 기반 가져오기
이미 서점 장바구니·찜 목록·SNS 저장 화면 등에 쌓여 있는 콘텐츠는 스크린샷이나 사진으로 한 번에 가져와 콘텐츠 정보를 인식하고 정리한다.
02

Problem — 관심은 많지만 경험으로 이어지지 않는다

주말마다 “오늘은 뭐 읽지, 뭘 보고, 뭘 듣지”라는 질문을 마주한다.

책, 음악, 영화, 전시, 장소 같은 콘텐츠는 이미 여러 플랫폼에 저장돼 있지만, 막상 무엇부터 시작해야 할지 몰라 선택으로 이어지지 않는다. 검색 → 발견 → 저장 → 잊음 → 다시 검색의 고리가 반복된다.

검증이 필요한 가설

저장과 정리의 불편이 실제 경험 부족의 핵심 원인인지, 또는 시간·의지·선택 부담 등 다른 요인이 더 큰지는 현재 데이터로 단정하지 않는다.

송림은 이를 사용자 조사와 MVP 행동 데이터로 검증한다.
03

Solution Architecture

송림의 핵심은 LLM API 자체가 아니라, 흩어진 콘텐츠를 구조화하고 동일 콘텐츠를 식별·연결해 선택지를 좁히는 기술 구조다.

이미지·목록 사용자가 발견한 콘텐츠
→
METADATA

공개 정보 보완 콘텐츠 정보 확보
→

↓

플랫폼 종속 리스크 대응

특정 플랫폼의 API나 크롤링에 전체 기능을 의존하지 않는다. 공유 텍스트와 공개 메타데이터를 우선 활용하고, 정보가 부족할 경우 공개 정보 보완과 AI 정제를 거친다. 플랫폼 정책 변화는 MVP 단계에서 추출 성공률과 사용자 보정률을 함께 확인한다.

동일 콘텐츠 식별

서로 다른 출처에서 저장된 같은 콘텐츠를 하나의 관심으로 연결하기 위해 엔티티 매칭 구조를 사용한다.

  • 책은 ISBN, 음반은 발매 단위 식별자와 발매정보 우선; 개별 곡의 ISRC는 트랙 매칭에 활용
  • 제목·저자·앨범·발매정보 정규화
  • 유사 콘텐츠 후보 및 신뢰도 기반 매칭
  • 낮은 신뢰도는 자동 병합하지 않고 사용자 확인

Fallback UX

초기 AI 자동화 단계에서 모든 콘텐츠를 100% 정확하게 인식하는 것은 현실적으로 어렵다. 송림은 오류 상황에서만 사용자가 최소 항목을 보정하도록 설계한다.

자동으로 인식한 정보가 맞나요?

책 · 음반 · 영화
제목 수정 / 저자·아티스트 수정 / 카테고리 수정

초기에는 상용 AI API를 활용하되, 운영 과정에서 콘텐츠 정규화 규칙·엔티티 매칭 로직·사용자 보정 데이터·행동 데이터를 축적해 송림만의 기술 자산으로 발전시킨다.

04

User Experience — 관심이 경험이 되는 과정

구조화된 콘텐츠는 사용자의 관심 데이터가 되고, 저장과 선택 행동을 거쳐 실제 경험으로 이어진다.

관심 → 저장 → 선택 → 경험 → 완료 → 취향 데이터 축적

송림은 새로운 콘텐츠를 추천하는 서비스가 아니라, 사용자가 이미 관심을 보인 콘텐츠 중 지금 경험할 하나를 선택하도록 돕는다.

경험 선택

“이번 주에는 이거 하나 해볼까요?”

송림은 사용자의 행동 데이터를 기반으로 경험 후보를 제안한다. 반복 저장 횟수(save_count)를 가장 먼저 고려하고, 같은 경우 최근 저장 시점 등을 보조 기준으로 활용한다.

한 번 저장한 콘텐츠는 관심으로, 여러 번 다시 저장한 콘텐츠는 더 강한 관심으로 해석한다.

금주의 추천과 오늘의 경험

금주의 추천은 저장된 경험 전 콘텐츠 중 하나를 다시 꺼내는 주간 제안이다. 사용자가 시작하면 같은 화면에서 해당 콘텐츠의 오늘의 경험을 이어간다. 경험 기간을 일주일로 제한하지 않으며, 미완료 콘텐츠는 다음 주에도 계속할 수 있다. 완료하면 주기가 끝나기를 기다리지 않고 다음 콘텐츠를 선택한다.

책

오늘의 페이지

읽고 있는 책의 오늘 독서를 이어가고, 읽은 위치를 필요할 때 기록한다. 매일의 독서 기록과 책 전체의 완료를 구분한다.

음반

오늘의 곡

선택한 음반의 곡을 오늘의 감상으로 연결한다. 곡의 감상 기록과 음반 전체의 완료를 구분한다.

영화

감상으로 연결

선택한 영화의 감상 행동으로 바로 연결한다. 감상 후 ‘오늘 봤어요’를 누르면 영화의 경험 완료로 기록한다.

최소 입력으로 시작과 완료 기록

‘시작하기’와 ‘완료했어요’로 경험 상태를 기록한다. 감상문·별점·상세 기록은 필수로 요구하지 않는다. 페이지나 곡의 일일 기록만으로 콘텐츠 전체를 자동 완료하지 않는다.

초기 전환 지표는 사용자가 직접 남긴 시작·완료 기록을 기준으로 측정한다. 구매·감상 링크 클릭은 별도 행동 신호이며 실제 경험 완료로 계산하지 않는다.

05

Forest Archive

숲은 완료된 문화 경험 데이터가 축적되고 시각화되는 개인 아카이빙 공간이다.

나무 = 완료된 콘텐츠 경험 1개
숲 = 사용자가 축적한 문화 경험 전체

숲은 기록 공간이면서 개인화의 기반이다. 관심 데이터와 경험 데이터가 쌓일수록 사용자의 취향 이해와 다음 경험 연결 가치가 높아진다.

올해의 숲

현재 연도의 경험 중·완료 콘텐츠가 반영된 화면보다 큰 하나의 2D 숲 장면을 탐색한다. 사용자는 숲 장면을 좌우로 이동하며 현재 연도의 경험 상태를 확인한다.

숲 장면 아래에는 다음 정보를 간단히 보여준다.

  • 책·음악·영화별 완료 수
  • 최근 경험한 콘텐츠 1개

월간 기록

선택한 달의 경험 흐름을 확인하는 기록 공간이다. 저장과 경험 완료 흐름을 한 달 단위로 다시 돌아볼 수 있다.

  • 월별 저장 수
  • 경험 완료 수
  • 카테고리별 완료 수
  • 주차별 경험 흐름
  • 해당 월 경험 콘텐츠

숲 기록

현재 연도를 포함한 연도별 숲 갤러리와 총 경험 수를 확인하는 아카이브 공간이다. 연도를 선택하면 화면보다 큰 하나의 숲 장면을 상하좌우로 이동하며 감상한다.

  • 완료된 연도별 숲 보관
  • 탑다운뷰·직교투영 방식
  • 나무 = 완료된 콘텐츠 경험 1개
  • 핀치·드래그 기반 탐색

올해의 숲에서는 경험 중인 콘텐츠와 완료된 콘텐츠의 상태를 구분해 보여준다. 완료 수와 연도별 완료 아카이브에는 완료된 경험만 집계한다. 숲의 개체를 선택하면 스크랩과 동일한 콘텐츠 상세로 연결되어 해당 콘텐츠의 정보와 경험 기록을 확인할 수 있다.

Forest Theme

Forest Theme는 사용자가 축적한 경험 공간을 자신의 취향에 맞게 표현하고 확장하는 요소다. 계절 테마, 기간 한정 테마, 특별 테마 등을 분기별 또는 시즌 단위로 제공하며, 지난 시즌 테마는 숲 기록에서 다시 적용하거나 구매할 수 있도록 한다.

06

MVP & Validation

초기에는 책·음반·영화를 대상으로 송림의 핵심 경험 흐름을 검증한다.

송림 MVP의 핵심 검증 대상은 사용자가 외부에서 발견한 콘텐츠를 자연스럽게 가져오고, 축적된 관심 중 하나가 실제 경험으로 이어지는 과정이다.

초기 사용자 경험 검증

첫 진입에서는 사용자가 이미 관심을 보였던 콘텐츠를 기반으로 송림 경험을 시작할 수 있는지 확인한다. 사용자는 콘텐츠를 직접 선택하거나 기존에 쌓아둔 콘텐츠를 이미지로 가져올 수 있다.

초기 입력 데이터는 사용자가 최종 확인한 항목만 관심 데이터로 저장하며, 이후 외부에서 가져온 동일 콘텐츠와 연결된다. 핵심 데이터 축적은 초기 온보딩뿐 아니라 사용자가 외부에서 발견한 콘텐츠를 송림으로 가져오는 과정에서 지속적으로 발생한다.

사용자 조사와 행동 검증

정량 설문 50명, 심층 인터뷰 15명과 프로토타입 사용성 테스트를 계획한다. 설문은 저장 습관과 미경험 이유를 확인하고, 인터뷰는 실제 저장 목록을 다시 꺼내는 상황을 살핀다. 사용성 테스트에서는 가져오기부터 선택·시작까지의 막힘을 관찰한다. 조사 참여 규모는 회원가입 목표와 구분한다.

검증 지표와 판단 기준

아래 수치는 초기 내부 검증 기준안이다. 첫 테스트 결과로 난이도와 표본 구성을 점검한 뒤 본 실험 전에 확정한다. 콘텐츠별 경험 기간 차이를 반영해 책·음반·영화를 나누어 보고, 비율과 함께 실제 표본 수를 기록한다.

검증 질문측정 방법초기 판단 기준
가져오기가 가능한가유효한 가져오기 시도 중 관심 데이터 생성 완료 비율. 입력 경로별로 매주 집계80% 이상. 실패율과 수동 보정률을 별도로 확인
저장 부담이 낮은가입력 제출부터 저장 완료까지 걸린 시간. 사용자 보정 시간 포함, 매주 중앙값과 상위 10% 지연 구간 확인중앙값 10초 이내. 지연·실패가 집중되는 경로 개선
관심이 시작으로 이어지는가신규 저장한 경험 전 사용자–콘텐츠 쌍 중 저장 후 28일 내 시작 기록 비율. 28일 관찰이 끝난 항목만 분모에 포함40% 이상을 가설로 검증. 저장→선택, 선택→시작도 분리 확인
완료 후 다시 선택하는가첫 완료 사용자 중 완료 후 28일 내 다음 콘텐츠를 선택한 사용자 비율. 관찰 기간이 끝난 사용자 기준30% 이상을 가설로 검증

수익화 검증과 확장 조건

모델먼저 확인할 것확장 조건
구매 연결도서부터 제휴 가능 여부·전환 추적 조건을 확인하고, 경험을 결정한 사용자의 구매 링크 클릭과 확인 가능한 구매 전환을 측정실제 계약 조건과 귀속 매출 확인. 클릭만으로 수익을 가정하지 않음
프리미엄경험 기록이 쌓인 사용자에게 테마·기록 확장 시안을 제시하고 이용 의향과 가격 반응 확인유료 시험 운영에서 결제·지속 이용 신호를 확인한 뒤 제공 범위 확대

운영과 비용 측정

초기에는 제휴 구매 연결부터 시작한다. 일반 경험 제안과 유료 프로모션은 명확히 구분하고, 파트너에게 제공할 성과는 집계 데이터 중심으로 설계한다.

가져오기 건당 AI 처리 비용, 사용자당 서버·데이터 비용, 채널별 사용자 확보 비용을 함께 기록한다. 제휴 수수료와 프리미엄 매출에서 직접 비용을 뺀 기여이익을 확인하고, 반복 이용이 늘 때 수익과 비용이 어떻게 변하는지 판단한다. 수수료율과 매출은 계약·실험 전 확정값으로 두지 않는다.

09

초기 사용자 확보 및 실행계획

콘텐츠를 자주 저장하지만 다시 꺼내 경험하는 데 어려움을 겪는 사용자부터 검증한다.

독서·취향 커뮤니티

실제 저장 목록으로 시작

독서모임과 콘텐츠 커뮤니티에서 이미 쌓아둔 관심 목록을 가진 참여자를 모집한다. 기존 저장 방식의 불편과 가져오기 과정을 관찰한다.

콘텐츠 SNS

저장하는 순간에 연결

‘저장해 두고 잊은 콘텐츠’를 소재로 사용 흐름을 소개한다. 유입 채널별 첫 저장과 첫 경험 시작을 확인한다.

소규모 그룹 테스트

하나를 골라 경험

모임 참여자가 실제 관심 콘텐츠를 선택하고 경험하도록 테스트한다. 중간 이탈 이유와 완료 후 다음 선택을 확인한다.

단계별 실행

착수 시점부터의 실행 계획이다. 단계별 결과를 바탕으로 다음 단계의 범위를 조정한다.

1–3개월

핵심 흐름 구현

실행 사용자 조사, 공유·이미지 입력, 콘텐츠 식별, 선택·시작·완료 구현

결과물 테스트 가능한 MVP와 행동 측정 기준

다음 조건 실제 콘텐츠로 전체 흐름을 수행하고 입력 실패 원인을 구분할 수 있음

4–6개월

사용자 행동 검증

실행 커뮤니티·소규모 그룹 테스트, 책·음반·영화별 전환 관찰

결과물 관찰 기간이 끝난 집단의 전환 데이터와 이탈 이유

다음 조건 입력과 경험 시작의 병목을 확인하고 우선 개선안을 정함

7–9개월

정확도·반복 이용 개선

실행 매칭·분류 보정, 오늘의 경험과 숲 재방문 흐름 개선

결과물 개선 전후 전환·보정률·다음 선택 비교

다음 조건 같은 기준으로 반복 사용 개선이 확인됨

10–12개월

수익화 가능성 검증

실행 구매 제휴 실험, 프리미엄 시안 평가, 소규모 파트너 협의

결과물 전환 신호·제휴 조건·실제 운영 비용

다음 조건 핵심 경험 전환과 수익 신호가 확인된 영역부터 확장 검토

채널 평가는 가입자 수보다 첫 저장·선택·시작과 반복 사용으로 판단한다. 채널별 모집 비용과 첫 경험 시작 사용자당 비용을 비교하고, 전환이 확인되는 채널에 집중한다.
