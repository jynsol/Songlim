서비스 개요

송림은 사용자가 외부에서 발견한 콘텐츠를 공유하면 AI가 정보를 자동으로 인식·분류하고, 서로 다른 출처의 콘텐츠를 하나의 관심 데이터로 연결해 실제 경험으로 이끄는 서비스다.

사용자는 콘텐츠를 발견하면 모바일 OS 기본 공유 기능(Share Sheet)을 통해 송림으로 전달한다. 정보가 부족하거나 공유 기능을 사용할 수 없는 경우에는 URL 복사·붙여넣기를 보조 경로로 제공한다. 다만 공유가 실제 사용의 진입장벽이 되는지는 아직 검증되지 않은 가설이며, 공유 이후의 수동 입력을 최소화하는 방식으로 초기 마찰을 낮추고자 한다. 또한 이미 서점 장바구니·찜 목록·SNS 저장 화면 등에 쌓여 있는 콘텐츠는 스크린샷이나 사진으로 한 번에 가져와 정리할 수 있도록 한다.

외부 콘텐츠 발견 / 기존 관심 가져오기→공유 / 이미지 가져오기→AI 자동 인식·분류→동일 콘텐츠 식별→관심의 씨앗→하나 선택→실제 경험→나무→숲
한 문장으로 말하면
송림은 새로운 관심을 추천하는 서비스가 아니라, 내가 이미 관심을 보였지만 놓치고 있던 것을 실제 경험으로 연결하는 서비스다.

사용자는 별도로 콘텐츠를 다시 검색하거나 일일이 분류할 필요 없이, 발견한 것을 송림으로 보내기만 하면 된다.

Problem — 관심은 많지만 경험으로 이어지지 않는다

주말마다 “오늘은 뭐 읽지, 뭘 보고, 뭘 듣지”라는 질문을 마주한다. 책, 음악, 영화, 전시, 장소 같은 콘텐츠는 이미 여러 플랫폼에 저장돼 있지만, 막상 무엇부터 시작해야 할지 몰라 다시 미루게 된다.

검증이 필요한 가설
저장과 정리의 불편이 실제 경험 부족의 핵심 원인인지, 또는 시간·의지·선택 부담 등 다른 요인이 더 큰지는 현재 데이터로 단정하지 않는다. 송림은 이를 사용자 조사와 MVP 행동 데이터로 검증한다.
검색 → 발견 → 저장 → 잊음 → 다시 검색이 반복된다.

기존 저장 기능은 보관에만 집중되어 있어, 다시 찾고 분류하고 무엇부터 볼지 결정하는 몫은 여전히 사용자에게 남는다. 송림은 이 문제를 “이미 관심을 보인 콘텐츠가 실제 경험으로 이어지지 않는다.”로 정의한다.

지원기간 동안 50명 정량 설문 + 15명 심층 인터뷰 + 프로토타입 테스트로 실제 고객 문제를 검증한다.

Solution — AI가 관심을 자동으로 정리한다

송림의 핵심은 LLM API 자체가 아니라, 흩어진 콘텐츠를 구조화하고 동일 콘텐츠를 식별·연결해 선택지를 좁히는 기술 구조다.

공유 텍스트 / 이미지·목록→OG 메타데이터→공개 정보 보완→AI 정제·분류→엔티티 매칭→관심 데이터
플랫폼 종속 리스크 대응
특정 플랫폼의 API나 크롤링에 전체 기능을 의존하지 않는다. 공유 텍스트와 공개 메타데이터를 우선 활용하고, 정보가 부족할 경우 공개 정보 보완과 AI 정제를 거친 뒤 사용자가 필요한 항목만 최소 보정하도록 설계한다. 플랫폼 정책 변화는 MVP 단계에서 실제 추출 성공률과 보정률을 함께 확인한다. 공유 정보가 부족하거나 기존 관심 목록을 한 번에 옮기는 경우에는 사용자가 직접 선택한 이미지·스크린샷을 보조 입력으로 활용한다.

동일 콘텐츠 식별

  • ISBN, ISRC 등 표준 식별자 우선
  • 제목·저자·앨범·발매정보 정규화
  • 유사 콘텐츠 후보 및 신뢰도 기반 매칭
  • 낮은 신뢰도는 자동 병합하지 않고 사용자 확인

Fallback UX

초기 AI 자동화 단계에서 모든 콘텐츠를 100% 정확하게 인식하는 것은 현실적으로 어렵다.

자동으로 인식한 정보가 맞나요?
책음반영화제목 수정

오류 상황에서만 카테고리·제목·저자/아티스트를 최소 수정한다.

초기에는 상용 AI API를 활용하되, 운영 과정에서 콘텐츠 정규화 규칙·엔티티 매칭 로직·사용자 보정 데이터·행동 데이터를 기술 자산으로 축적한다.

사용자 경험 — 관심이 숲이 되는 과정

AI가 정리한 콘텐츠는 ‘관심의 씨앗’이 되고, 사용자의 행동이 쌓이며 실제 경험으로 이어진다.

저장→반복 저장→선택→시작→완료
“이번 주에는 이거 하나 해볼까요?”
반복 저장 횟수를 가장 먼저 보고, 같은 횟수라면 최근 저장 시점 등을 보조 기준으로 하나를 제안한다. 한 번 저장한 것은 관심, 여러 번 다시 저장한 것은 더 강한 관심으로 해석한다.

공유 포인트
월간에는 “이번 달 34개를 저장했고 13개를 경험했어요”처럼 저장과 경험을 함께 보여주고, 연말에는 한 해 동안 경험한 콘텐츠로 완성된 ‘올해의 숲’을 공유한다. 단순 소비량 자랑보다 관심이 실제 경험으로 바뀐 과정을 송림의 차별적인 기록·공유 포인트로 삼는다.

나무는 포인트가 아니라 무엇에 관심을 가졌고 무엇을 실제로 경험했는지를 기록하는 시각적 장치다. 송림의 기록 화면은 같은 정보를 반복해서 보여주지 않고 기간에 따라 역할을 나눈다.

올해의 숲

‘나의 숲’의 기본 화면이다. 해당 연도에 경험 중이거나 완료한 책·음반·영화를 2D 가로 스크롤 숲에서 직접 둘러본다. 사용자는 숲을 좌우로 이동하고 각 개체를 선택해 콘텐츠 상세를 확인한다.

월간 기록

숲 대신 숫자·간단한 그래프·콘텐츠 목록으로 이번 달을 빠르게 돌아본다. 이번 달 저장한 콘텐츠 수와 실제 경험한 콘텐츠 수, 책·음반·영화별 완료 수, 주차별 경험 수, 가장 많이 저장한 콘텐츠, 저장해두다 이번 달 경험한 콘텐츠 등을 보여준다.

지난 숲

연도가 바뀌면 이전 연도의 숲을 한 장의 대표 이미지와 핵심 숫자로 다시 감상할 수 있다. 과거 숲을 다시 탐색 맵처럼 돌아다니지는 않으며, 자세한 저장·경험 데이터와 콘텐츠 목록은 별도의 연간 리포트에서 확인한다. 연도별 기본 숲 디자인은 달라질 수 있지만, MVP에서는 개인 데이터에 따라 테마가 변하지 않고 새·토끼·개구리 같은 작은 환경 애니메이션만 가볍게 제공한다.

월간은 기록을 읽는 화면, 연간 숲은 기록을 감상하는 화면
월간 공유는 “이번 달 이만큼 저장했고, 이만큼 경험했어요”라는 가벼운 리캡으로, 연간 공유는 “올해 이렇게 취향의 숲을 키웠어요”라는 완성된 결과물로 만든다. 지난 숲 상세는 대표 이미지와 핵심 숫자만 보여주고, 저장 수·월별 추이·가장 많이 저장한 콘텐츠·연간 경험 콘텐츠 전체 등은 별도 연간 리포트에서 확인한다. 저장 수와 경험 수는 경쟁이나 목표 달성 점수가 아니라 사용자가 자신의 관심이 실제 경험으로 얼마나 이어졌는지 돌아보는 기록으로 사용한다.

초기 MVP에서는 ‘시작’과 ‘경험 완료’를 별도의 상세 기록 없이 최소한의 사용자 입력으로 기록한다. 올해의 숲에는 해당 연도 기록을 모두 탐색할 수 있게 하고, 월간 기록과 지난 숲에서 기간별로 다시 확인한다. 이후 데이터가 축적되면 링크 클릭 등 행동 신호를 활용한 측정을 검토한다.

MVP 및 검증 전략

초기에는 책 + 음반 + 영화로 전체 사용자 경험을 검증한다.

초기 온보딩
첫 진입 시 사용자는 책·음반·영화를 약 10개 직접 선택하거나, 서점 장바구니·찜 목록·SNS 저장 화면 등 이미 쌓아둔 콘텐츠를 사진으로 가져와 시작할 수 있다. 두 방식을 함께 사용할 수도 있다. 직접 선택 시 각 콘텐츠에 대해 관심 있음 / 경험함 / 싫음의 상태를 선택하고, 모르는 콘텐츠는 건너뛸 수 있다. 가져온 콘텐츠는 사용자가 최종 확인한 항목만 관심 데이터로 저장한다. 이렇게 확보한 초기 관심·경험 데이터는 이후 외부에서 공유한 동일 콘텐츠와 하나의 데이터로 연결한다.
금주의 추천과 오늘의 경험
사용자가 직접 관심을 표시하거나 저장한 ‘경험 전’ 책·음반·영화 중 하나를 금주의 추천으로 다시 꺼내 제안하고, 사용자가 경험을 시작하면, 같은 화면에서 매일 해당 콘텐츠의 오늘의 경험을 제공한다. 금주의 추천은 주간 추천 단위이지만 경험 기간을 일주일로 강제하지 않으며, 완료하면 바로 다음 콘텐츠를 선택할 수 있다. 음반은 ‘오늘의 곡’, 책은 ‘오늘의 페이지’로 일일 경험을 제공한다. 영화는 별도의 일일 조각 명칭 없이 바로 감상 행동으로 연결하고, ‘오늘 봤어요’가 최종 완료가 된다. 이를 통해 선택이 실제 경험으로 이어지고 지속되도록 돕는다. 완료하지 못한 콘텐츠는 다음 주에도 이어갈 수 있다.

핵심 기능

  • 회원가입 / 로그인
  • 책·음반·영화 초기 취향 온보딩
  • 금주의 추천 / 오늘의 경험(책: 오늘의 페이지 / 음반: 오늘의 곡 / 영화: 바로 감상)
  • 외부 콘텐츠 공유
  • 공유 텍스트·OG 정보 추출
  • AI 정보 정제·자동 분류
  • 동일 콘텐츠 식별
  • 관심 저장 / 관심 목록 · 동일 콘텐츠 반복 저장 횟수 누적 및 ‘n번 저장’ 표시
  • Fallback 수정
  • 일일 경험 기록 / 콘텐츠별 완료 처리(영화는 ‘오늘 봤어요’ 즉시 완료)
  • 씨앗 → 싹 → 덤불 → 나무 → 큰 나무 성장 기록(큰 나무는 실제 완료 시에만)
  • 완료 후 선택형 1~5점 평가
  • 올해의 숲 · 해당 연도의 경험 중/완료 콘텐츠를 2D 가로 스크롤 숲에서 직접 탐색 · 숲 자체 드래그/스와이프 · 작은 사용자 위치 표시 이동 · 개체 선택 시 콘텐츠 상세 연결
  • 월간 기록 · 월별 저장 수 / 경험 완료 수 / 책·음반·영화별 완료 수 / 주차별 간단 그래프 / 반복 저장 및 저장→경험 사례 / 월간 공유 카드
  • 지난 숲 · 이전 연도의 숲을 대표 이미지 + 핵심 숫자로 다시 보기 · 연도별 갤러리 · 연간 공유 카드
  • 연간 리포트 · 연도별 저장 고유 수 / 경험 완료 수 / 책·음반·영화별 완료 수 / 월별 경험 추이 / 반복 저장 및 저장→경험 사례 / 연간 경험 콘텐츠 목록
  • 연도별 기본 숲 디자인 + 새·토끼·개구리 등 작은 환경 애니메이션
  • 행동 데이터 수집

  • 복잡한 개인화 추천

  • B2B 기능
  • 전시·공연·장소 등 추가 카테고리 확장

나의 숲은 게임 맵이 아니라 사용자가 실제로 경험한 콘텐츠가 쌓이는 기록 시각화로 한정한다. MVP에서는 올해의 숲을 직접 돌아보고, 월간 기록으로 숫자와 콘텐츠를 빠르게 회고하며, 연도가 바뀌면 지난 숲을 연도별 대표 이미지와 핵심 숫자로 다시 감상할 수 있게 한다. 자세한 연간 데이터는 별도의 연간 리포트에서 제공한다. 숲 디자인은 연도별 기본 테마를 사용할 수 있지만 사용자 데이터에 따라 숲 자체가 달라지는 기능은 MVP에서 제외한다. 점프·레벨·아이템·수집 보상·경쟁 같은 별도 게임 시스템도 포함하지 않는다. 위 확장 항목의 구체적인 단계와 시점은 7장 BM 및 Scale-up에서 다룬다.

핵심 검증 질문: “콘텐츠를 송림으로 보내면 AI가 자동으로 정리하고, 저장된 관심 중 하나가 실제 경험으로 이어지는가?”

여기서 정리만으로 행동 전환이 보장된다고 가정하지 않는다. 송림의 역할은 의지를 강제로 만드는 것이 아니라, 이미 관심을 보인 콘텐츠 중 하나를 다시 꺼내 선택 비용을 낮추고 시작하기 쉽게 만드는 것이다. 특히 같은 콘텐츠를 여러 번 저장한 행동은 사용자가 반복적으로 관심을 보인 신호로 보고 우선적으로 다시 보여준다.

북마크 서비스가 저장에, 콘텐츠 플랫폼이 발견·추천에 집중한다면 송림은 외부에서 발견한 콘텐츠를 AI가 자동으로 관심 데이터로 만들고, 동일 콘텐츠를 연결한 뒤 실제 경험까지 이어준다.

AI 모델 자체가 아니라 콘텐츠 엔티티 식별·관심 데이터화·행동 전환 구조가 송림의 핵심 기술 자산이다.

BM 및 Scale-up

송림의 수익화 지점은 단순 노출이 아니라 사용자가 관심 콘텐츠를 실제 경험·구매하기로 결정하는 순간에 둔다.

관심 저장→금주의 추천→경험 선택→구매·이용 연결→경험 완료→평가

단계별 수익모델

  • 1단계 · 구매 연결: 책을 우선 대상으로 구매 링크와 제휴를 붙여 저장 → 추천 → 구매 전환이 실제로 발생하는지 확인한다.
  • 2단계 · 콘텐츠 프로모션: 출판사·음반사·영화 배급사 등과 특정 콘텐츠 캠페인을 운영하고, 저장·선택·완료 반응을 성과 지표로 제공한다.
  • 3단계 · B2B 인사이트: 사용자 규모가 확보되면 저장 → 선택 → 경험 완료 → 평가까지의 집계 데이터를 콘텐츠 반응 인사이트로 제공한다.
  • 4단계 · B2C 유료 기능: 현재 연도의 기본 숲과 사용자의 과거 연간 기록 열람은 무료로 유지한다. 기록 가치가 충분히 검증된 뒤, 지난 연도의 숲 디자인을 현재 숲이나 공유 카드에 다시 적용하는 선택형 테마를 ‘도토리’로 이용할 수 있게 하고, 고급 통계·보관 기능 등은 별도로 검증한다.

운영 원칙

  • 초기에는 직접 판매·재고를 보유하지 않는다.
  • 일반 추천과 유료 프로모션은 명확히 구분한다.
  • 첫 수익화는 사용자가 이미 경험을 결정한 뒤의 구매·이용 연결부터 검증한다.
  • B2B와 구독은 사용자·데이터 규모가 확보된 뒤 확장한다.
  • 과거 기록 자체는 유료화하지 않는다. 지난 숲은 언제든 다시 볼 수 있게 하고, 도토리는 과거 연도 디자인을 다시 사용하는 선택형 꾸미기 요소에만 적용한다.

실행 가능성
도서·음반은 이미 온라인 유통과 상품 DB가 잘 갖춰진 분야다. 알라딘은 현재 사업자 대상 공동마케팅·제휴와 OpenAPI/상품DB 창구를 운영하고 있어, 송림이 콘텐츠를 식별해 구매 페이지로 연결하고 제휴를 실험할 수 있는 실제 경로가 존재한다. 제휴 수수료와 조건은 계약 전 확정값으로 가정하지 않고 MVP에서 직접 검증한다.

송림의 수익성은 단순 MAU보다 저장 → 추천 → 경험 시작 → 구매·이용 → 완료가 얼마나 반복되는지에 달려 있다. 사용자 규모가 늘어나는 과정에서 AI API·서버·데이터·사용자 확보 비용을 함께 측정해 손익분기 가능성을 판단한다.

제휴 경로 확인 알라딘 파트너십 가이드(공동마케팅·제휴, OpenAPI/상품DB) 및 OpenAPI 안내 확인. 실제 계약 여부와 수수료율은 별도 협의 사항.

장기적으로는 책·음반·영화에서 전시·공연·장소 등으로 경험 범위를 넓힐 수 있지만, 확장은 현재 MVP의 저장 → 선택 → 경험 완료 전환이 먼저 검증된 뒤 진행한다.

PSST — 사업 추진 구조

P · Problem

“오늘은 뭐 읽지, 뭘 보고, 뭘 듣지” — 주말마다 반복되는 흔한 고민이다. 콘텐츠는 SNS·서점·스트리밍 앱에 흩어져 있고, 저장은 쉽지만 그중 무엇을 실제로 경험할지는 여전히 사용자의 몫으로 남는다.

S · Solution

송림은 이 넓은 선택지를 좁혀, 흩어진 고민이 실제 취향으로 자랄 수 있도록 돕는다. 공유 텍스트·OG → AI 자동 정제·분류 → 동일 콘텐츠 엔티티 매칭 → 관심 데이터 → 금주의 추천 → 실제 경험 순으로, 사용자는 발견한 콘텐츠를 공유하기만 하면 나머지는 송림이 정리한다.

S · Scale-up

책·음반·영화에서 전시·공연·여행·장소로 콘텐츠 범위를 넓히고, 콘텐츠 구매 연계 → 브랜드·콘텐츠 제휴 → 오프라인 공간 제휴 순으로 수익 구조를 단계적으로 확장한다.

대표자 1은 약 4년간 판교 IT 업계에서 고객 대응·운영·구매·재고관리 등을 경험하고 장기간 독서 기록을 축적해 문제를 발견하고 서비스 기획을 담당한다.

두 대표자는 문제 발견 → 제품 기획 → 기술 구현 → 사용자 검증을 함께 수행한다.

MAU는 공개 다운로드 수에서 기계적으로 환산하지 않는다. 1,000명은 누적 회원 5,000명 중 월 1회 이상 실제로 송림을 사용하는 사용자를 20% 확보하겠다는 내부 목표치다. 기록형 서비스는 저장·선택·경험 기록이 반복되어야 가치가 생기므로, 단순 가입자보다 월간 활성 사용자와 핵심 퍼널 반복률을 함께 본다.

지원기간 실행

50명 정량 설문 + 15명 심층 인터뷰 + 프로토타입 사용성 테스트를 통해 문제의 실재성과 행동 전환을 검증한다.

핵심 행동·기술 KPI

저장 → 선택 → 시작 → 경험 완료 → 다음 선택을 핵심 퍼널로 관리하며, 콘텐츠 정보 추출 성공률·AI 자동분류 정확도·동일 콘텐츠 식별 정확도·수동 보정률도 함께 측정한다.
